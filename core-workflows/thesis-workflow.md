# Thesis Workflow

适用场景：毕业设计、文献综述、开题报告、中期检查、实验记录、论文初稿、答辩材料。

## 核心目标

- 先把任务拆清楚，再开始查资料或写作。
- 尽量把会议结论、实验结果、文档输出串成一条线。
- 每次产出都能沉淀为后续可复用的材料。

## 标准流程

### 1. 先定任务和边界

先说清楚你这一轮到底要完成什么，例如：

- “这周要完成相关工作综述第二节”
- “我要准备开题答辩 PPT”
- “我要整理实验结果并写实验设计部分”

优先调用：

- `create-plan`
- `planing-with-file`

产出目标：

- 一个可执行的短计划
- 当前任务的 `plan.md`

### 2. 做文献和背景研究

如果目标是资料梳理、文献比较、综述写作，优先调用：

- `content-research-writer`
- `hv-analysis`
- `notion-research-documentation`

使用建议：

- 普通文献综述、带引用整理：`content-research-writer`
- 想系统研究一个方向、方法、模型、产品：`hv-analysis`
- 资料已经在 Notion 里：`notion-research-documentation`

产出目标：

- 文献笔记
- 相关工作结构
- 对比表
- 可直接进入论文的段落草稿

### 3. 处理导师会、组会、讨论记录

如果你有会议录音、转写、聊天记录或笔记，优先调用：

- `meeting-notes-and-actions`
- `meeting-insights-analyzer`

使用建议：

- 想要“纪要 + 决策 + 待办”：`meeting-notes-and-actions`
- 想分析“风险、争议点、真正结论”：`meeting-insights-analyzer`

产出目标：

- 会议纪要
- 下一步行动清单
- 需要补做的实验或补写的段落

### 4. 写论文正文

进入写作后，根据你手上的素材状态切换：

- 已经有草稿，需要改学术表达和结构：`edit-article`
- 只有材料和提纲，需要扩成完整文本：`khazix-writer`

产出目标：

- 章节初稿
- 语句优化稿
- 更适合导师阅读的版本

### 5. 整理实验、数据和表格

如果涉及指标计算、图表前的数据清洗、对比表制作，优先调用：

- `spreadsheet-formula-helper`

产出目标：

- 干净的数据表
- 正确的公式
- 可用于论文和答辩的对比结果

### 6. 做正式交付物

当你要产出可提交的文件时，优先调用：

- `paperjsx`
- `doc`
- `pdf`

使用建议：

- 要一口气生成 PPT、Word、表格、PDF：`paperjsx`
- 要精修 `.docx` 版式和内容：`doc`
- 要检查 PDF 最终展示效果：`pdf`

产出目标：

- 开题答辩 PPT
- 中期报告
- 论文初稿或终稿
- 实验报告 PDF

### 7. 收尾和归档

每完成一个阶段，就整理一次：

- `file-organizer`
- `neat-freak`
- `obsidian-vault`

产出目标：

- 文件结构更清楚
- 文档和实际进展同步
- 方便下次继续接着做

## 常见任务怎么走

### 场景一：写文献综述

1. `create-plan`
2. `planing-with-file`
3. `content-research-writer`
4. `hv-analysis`
5. `edit-article`
6. `pdf` 或 `doc`

### 场景二：准备开题或答辩

1. `create-plan`
2. `meeting-notes-and-actions`
3. `spreadsheet-formula-helper`
4. `paperjsx`
5. `pdf`
6. `file-organizer`

### 场景三：整理导师反馈后改稿

1. `meeting-insights-analyzer`
2. `create-plan`
3. `edit-article`
4. `doc`
5. `neat-freak`
